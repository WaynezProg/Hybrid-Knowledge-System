# 028-date-range-cross-year-and-counts — 跨年的月/日區間與數量範圍

- 日期：2026-11-15
- 狀態：已實作
- 範圍：session-memory 查詢的日期區間解析（`parse_session_memory_date_range`）中，寫了月份的 `M/D-M/D` 形式與只寫日數的 `N~M` 形式。

## 1. 動機

1. **跨年的月/日區間算錯年份。** `M/D-M/D` 一律補上今年，再把順序顛倒的區間對調。2027-01-05 問 `12/28-1/3`，會解析成 2027-01-03 到 2027-12-28：將近一整年，大半還在未來。提問的人指的是 2026-12-28 到 2027-01-03 這六天。
2. **一般的數字範圍被當成日期。** `N~M` 的 pattern 吃下任何兩個一到兩位數，`列出 3~5 個重點` 會解析成當月 3 日到 5 日，`commands/query.py` 因此把那幾天的 session memory 混進不相關的查詢。

## 2. 決策

| # | 決策 |
|---|---|
| 1 | `M/D-M/D` 起始月份大於結束月份時，比較兩種讀法：跨年（起點在前一年）與寫反（同一年、對調）。取天數較短的那種。`12/28-1/3` 跨年是 6 天、寫反是 359 天，讀成跨年；`5/10-3/1` 跨年是 295 天、寫反是 70 天，仍讀成寫反並 `swapped=true` |
| 2 | 讀成跨年時，結束年從明年往回試，取起點不在今天之後、最近的那一段。12/30 問 `12/28-1/3` 是今年 12/28 到明年 1/3（區間已開始，與 027 決策 3 一致）；1/5 問是去年 12/28 到今年 1/3。跨年的結果 `swapped=false` |
| 3 | 起始月份不大於結束月份的 `M/D-M/D` 不變，照 027 決策 5 依字面解析 |
| 4 | `N~M` 後面接數量、時長或單位（個、項、點、條、次、天、週、月、年、人、頁、章、題、%、英文字母等）時不是日期區間，回傳 `None` |
| 5 | `N~M` 前面是「第」、英文字母或小數點，或後面接小數點或更多位數時（`第2~4題`、`v1~3`、`1.5~2.5`、`3~555`），不是日期區間 |
| 6 | `25~27 之間`、`25~27日`、`25～27號` 仍是日期區間，行為照 027 |

## 3. 契約變更

- Response schema、route 名稱、trace step 的 kind 與 `detail` 欄位都沒有變。
- 行為變更：跨年的 `M/D-M/D` 解析成正確的跨年區間；帶單位的數字範圍不再產生 `session_memory_intent` 的 `date_start`／`date_end`，改走一般查詢。
- CLI、MCP 與 HTTP 的 query 入口共用同一個解析函式，行為一併改變。

## 4. 驗證

`tests/unit/routing/test_session_memory_date_range.py`：

- 2027-01-05 與 2026-12-30 問 `12/28-1/3`，都得到 2026-12-28 到 2027-01-03。
- `5/10-3/1` 仍對調成 03-01 到 05-10、`swapped=true`。
- 九種數量／序號／比例／小數的寫法回傳 `None`；`列出 3~5 個重點` 沒有日期 intent。
- `25~27 之間`、`25~27日`、`25～27號` 仍解析成日期區間。

把解析函式換回變更前的版本後，12 個測試失敗。

## 5. 不在範圍內

- 沒有跨年、但整段在未來的 `M/D-M/D`（1 月問 `12/20-12/25`）仍依 027 決策 5 解析成今年，會落在未來。
- 當月沒有那一天時（11 月問 `30~31`）仍直接回傳 `None`，不改試上個月（027 第 5 節）。
- 單位清單是列舉式的；沒列到的單位（例如罕見量詞）仍可能被當成日期。
