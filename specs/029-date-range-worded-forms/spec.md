# 029-date-range-worded-forms — 用「月／日」與「到／至」寫的日期區間

- 日期：2026-11-15
- 狀態：已實作
- 範圍：session-memory 查詢的日期區間解析（`parse_session_memory_date_range`）中，沒寫年份的月/日區間。

## 1. 動機

沒寫年份的月/日區間原本只認 `M/D` 加上 `-`、`~`、`－`（`12/28-1/3`）。中文問句常見的寫法都回傳 `None`，問句因此沒有 `date_start`／`date_end`，不會去找那幾天的 session memory：

- `12月20日到1月5日`、`12月20日至1月5日`、`12月20日~1月5日`、`12月20號到1月5號`
- `12月20日到25日`（第二個月份省略）
- `12/20到1/5`、`12/20至1/5`、`12/20 到 1/5`

## 2. 決策

| # | 決策 |
|---|---|
| 1 | `M/D` 區間的連接詞加上 `到`、`至`、`～`，兩側可有空白 |
| 2 | 新增 `M月D日` 形式：`日`、`號`（`号`）可省略，連接詞同決策 1，數字與「月／日」之間可有空白 |
| 3 | 第二個月份可省略，視為與起始同月：`12月20日到25日` 等同 `12/20-12/25` |
| 4 | 解析出月、日之後與 `M/D-M/D` 走同一段邏輯，結果與對應的斜線寫法相同：跨年、寫反對調（028 決策 1、2）、落在未來照字面（027 決策 5）、不存在的日期（`2月30日到3月1日`）回傳 `None` |
| 5 | 必須有「月」且後面接日數才算：`3月到5月的營收`、`1到5個重點`、`3點到5點` 不是日期區間，行為與變更前相同 |
| 6 | 省略第二個月份、結尾數字又沒寫「日／號」時，後面接 028 決策 4 的單位或小數點就不是日期區間（`12月20日到3個重點`、`1月5日到10次`） |
| 7 | 前面有「年」的寫法（`2026年12月20日到1月5日`）不在這裡補今年，不是區間，行為與變更前相同 |

## 3. 契約變更

- Response schema、route 名稱、trace step 的 kind 與 `detail` 欄位都沒有變。
- 行為變更：上述寫法現在會產生 `session_memory_intent` 的 `date_start`／`date_end`，與斜線寫法走同一條路徑。
- CLI、MCP 與 HTTP 的 query 入口共用同一個解析函式，行為一併改變。

## 4. 驗證

`tests/unit/routing/test_session_memory_date_range.py`：

- 九種寫法在 2026-11-15、2026-12-30、2027-01-10 三個「今天」下，結果都與 `12/20-1/5` 相同。
- `12月20日到25日`、`12月20號~25號`、`12月20日到25 行程` 解析成同月的 20 日到 25 日。
- `5月10日到3月1日` 與 `5/10-3/1` 相同，`swapped=true`。
- 九種非日期或不存在日期的寫法回傳 `None`。
- `analyze_session_memory_intent` 對「月日」與「到」的寫法，回傳的 intent（含 workspace、status）與斜線寫法相同。

## 5. 不在範圍內

- 混用兩種寫法（`12/20到1月5日`）與只寫日數的「到」（`25日到27日`、`25到27`）仍不是日期區間。
- 省略第二個月份時不推測下個月：`12月25日到3日` 等同 `12/25-12/3`，會對調。
- `N~M <詞>` 的數量／日期判斷（028 決策 4）維持列舉式。評估過用問句裡的提示詞（進度、做了什麼）或日數大小來判斷：`3~5 項任務的進度` 與 `25~27 項目進度` 的提示詞相同、`每頁 10~12 行` 的數字也不小，兩種訊號都只是把誤判換到另一批問句。把 `項目` 加進一般詞清單則會讓 `3~5 項目標` 被當成日期。
